Implement the Like interaction according to the confirmed application behavior.

If the real app behavior has been captured, follow it exactly.

If exact behavior is not documented, use a restrained, platform-consistent interaction while keeping the implementation modular.

Default state

* Inactive Like icon
* Original Like count

Example:

Use the actual count shown in the supplied reference when known.

Active state

When Like is triggered:

1. Like control enters a pressed state.
2. Icon changes to active appearance.
3. Like count increases by one.

5. The post remains visually stable.

* Confetti
* Large particles
* Excessive scaling
* Flash effects

unless the real app explicitly does so.

Toggle behavior

If the actual app does not support it or has not been verified, keep the interaction state modular and document the assumption.
